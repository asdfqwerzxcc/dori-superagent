# omo-stats UI 계획 (2026-11-19)

전제: 데이터 소스가 **로컬 세션 로그(omo/codex)** + (추가 예정) **OpenRouter 청구**, **Claude Enterprise**. 화면은 "한 사람이 10초 안에 비용 진실을 읽는 계기판"이다.
기존 확정 방향 유지: obsidian 기본 테마, 모노 tabular 숫자, 액센트는 화면의 몇 %만, 차트 하나만 주인공.

## 1. 화면 4개

| 화면 | 답하는 질문 | 데이터 |
|---|---|---|
| **Usage (홈)** | "이번 달 얼마 썼고, 어디서 늘었나" | 정규화 행 집계(총액·일별·모델별) |
| **Sessions** | "어느 세션이 비쌌나" | 세션별 합계 → 모델 구간 → 메시지 |
| **Reconcile** | "로컬 추정과 실제 청구가 얼마나 다른가" | 소스별 총액 + 차이 |
| **Settings** | "무엇을 어디서 읽나" | 소스 연결·테마·갱신 주기 |

## 2. 데이터 → 화면 매핑

정규화 행: `{sessionId, ts, provider, modelId, input, output, cacheRead, cacheWrite, costUsd, source}`

- Usage 히어로 = `SUM(costUsd)` (선택 기간), 서브라인 = `세션 수 · 소스 라벨 · 산정 커버리지`
- 차트 = 일별 합계(24슬롯), 모델 스트립 = 모델별 합계
- Sessions 목록 = `GROUP BY sessionId` (비용·토큰·캐시율·모델 수)
- 세션 상세 = `model_change` 경계로 나눈 모델 구간 타임라인
- Reconcile = `source`별 총액 + `로컬 추정 vs 청구` 차이(%)

## 3. 상태 설계 (이게 제품의 절반)

- **부분 실패**: 소스 하나가 안 읽히면 총액을 숨기지 말고 **그 소스를 `미연결`로 표시**하고 나머지로 총액을 낸다. 커버리지(%)를 항상 숫자로 노출.
- **스테일**: 마지막 갱신 시각을 시그니처(`● 기록 중 │ 방금`)로. 5분 넘으면 `지연`으로 바꾼다.
- **빈 상태**: "세션 로그 없음"과 "필터 결과 없음"을 구분해서 카피한다.
- **로딩**: 스켈레톤 대신 **이전 값 유지 + 우상단 점멸** (숫자가 깜빡이며 사라지면 계기판 신뢰가 깨진다).

## 4. 정직성 규칙 (디자인이 아니라 데이터 규칙)

1. **총액은 하나**: 두 개의 총액을 나란히 두지 않는다. 소스가 다르면 `Reconcile`에서만 나란히 본다.
2. **추정 표기**: 로컬 costUsd는 omo 계산값 → 라벨 `추정`. 청구서 숫자와 섞지 않는다.
3. **귀속**: 모든 숫자는 `provider/modelId`까지 내려가 설명 가능해야 한다(클릭 → Sessions → 메시지).

## 5. 구현 순서

- **P0**: 로컬 세션 로더 + 정규화 테이블 + Usage 홈(SQLite). 소스 라벨 `omo-local` 하나.
- **P1**: Sessions·세션 상세 + Reconcile 골격(청구 소스는 비어 있는 상태로 UI 먼저).
- **P2**: OpenRouter usage API 연결 → Reconcile 실데이터, 커버리지 % 계산.
- **P3**: Claude Enterprise 데이터(수동 업로드 CSV라도) → 시트 비용 반영.
- **P4**: 실시간(파일 워치) — 신규 세션 반영 지연 1분 이내.

## 6. 시각 규칙 요약

- 숫자: JetBrains Mono tabular, `$63.30` / `98.4%` 한 포맷.
- 라벨/카피: Pretendard, 영어는 데이터 명사만(API·token·endpoint).
- 액센트: 트레이스 선, 최신 버킷, 활성 행, 레코더 점 — 그 외 중립 램프.
- 차트: 히어로 176px 하나, 모델 스트립 112px, y틱 3개.
- 헤더 44~52px 한 줄, 사이드바 300px, 콘텐츠 시작선 1060px.

- omo-stats 레포가 이 머신에 체크아웃돼 있지 않다 → 작업 전에 경로/원격 확인 필요.
