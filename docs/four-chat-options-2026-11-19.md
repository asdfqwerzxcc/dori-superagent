## 각 도구의 결정적 장단

**Zulip** — 이긴다: 에이전트가 일하기 가장 좋은 API(이벤트 큐·봇·메시지 편집), topic=레인 매핑, 검색. 진다: 컴포넌트 3개 운영, UX 재교육.

**Mattermost** — 이긴다: Slack 감각 + **GitLab SSO를 팀 에디션에서 바로**, 플러그인 생태계. 진다: 에이전트 이벤트 모델이 투박, 스레드가 약함.

**Element(Matrix)** — 이긴다: E2E·연합·브리지 생태계(Slack 병행). 진다: 운영 무겁고, **봇이 암호화 룸을 못 읽어 에이전트 채널과 상충**, 검색 약함.

**Orbit** — 이긴다: 운영 최경량(바이너리+SQLite), 태스크·문서·채팅 통합, MCP. 진다: **매우 젊음**(이번 주 시작), 채팅 기능 얕음, 플러그인 없음.

## 결론(권장 순서)

1. **Zulip + GitLab** — 에이전트 중심 운영이면 이 조합. 레인=topic, 이슈=GitLab. slack은 미국 채널만 브리지.
2. **Mattermost + GitLab** — 사람 중심·Slack 감각 유지가 우선이면. GitLab SSO가 즉시 붙는 게 실무 이점.
3. **Orbit** — "태스크·문서·채팅을 한 화면"이 목표이고, 젊은 프로젝트 리스크를 감수할 때만.
4. **Element** — E2E/연합이 규정 요구일 때만. 에이전트 채널은 평문으로 분리해야 함.

## 미확인

- Zulip self-host의 SAML/OIDC 세부 티어, Mattermost 팀 에디션 SSO 범위는 버전별로 달라 **설치 버전에서 확인 필요**.
- Orbit의 OIDC/SSO 성숙도와 채팅 API 깊이는 문서만으로 판단(실측 미확인).
